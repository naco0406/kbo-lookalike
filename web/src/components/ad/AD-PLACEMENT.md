## 기술 구현

### 핵심 파일

| 파일 | 역할 |
|------|------|
| `components/ad/ad-container.tsx` | AdContainer 컴포넌트 — 애드핏 스크립트 로딩, 렌더링, 정리 |
| `components/ad/ad-slots.ts` | 광고 슬롯 설정 — unitId, 사이즈 중앙 관리 |

### 카카오 애드핏 + React SPA 통합 방식

`ba.min.js`는 실행 시점에 DOM 내 `<ins class="kakao_ad_area">`를 탐색하여 광고를 렌더링한다.
React SPA에서는 페이지 전환 시 새로운 `<ins>`가 동적으로 추가되므로, 이미 로드된 스크립트가 이를 인식하지 못한다.

**해결**: 컴포넌트 mount마다 `<ins>` + `<script>` 쌍을 imperative하게 DOM에 삽입한다.
`<script>`는 브라우저 캐시에서 즉시 실행되어 새 `<ins>`를 발견 → 광고 렌더링이 보장된다.

```
mount → <ins> 삽입 → <script> 삽입 → ba.min.js 재실행(캐시) → <ins> 발견 → 광고 렌더
unmount → <ins> 제거 + <script> 제거 (메모리 누수 방지)
```

### 광고 로드 감지

- `MutationObserver`로 `<ins>`의 `style` 속성 변화 감시
- `display:none` → `display:block` 전환 시 skeleton 해제
- 5초 내 미렌더링 시 컴포넌트 자체를 DOM에서 제거 (빈 박스 UX 오염 방지)

## 디자인 원칙

### DO

- 콘텐츠와 콘텐츠 사이 자연스러운 여백에 배치 (`py-6` = 24px 상하)
- "광고" 라벨 항상 표기 (10px, muted-foreground)
- 서비스 디자인 시스템과 동일한 `border-radius: 20px`, `bg-card`, `border-border` 적용
- 한 viewport에 광고 최대 1개
- 광고 로드 실패 시 컴포넌트 완전 제거 (빈 박스 남기지 않음)
- 로드 전 skeleton으로 CLS 방지

### DON'T

- 게임 플레이 도중 광고 노출
- 사진 분석/로딩 중 광고 노출
- 모달/상세 팝업 위에 광고 오버레이
- 하단 고정(fixed bottom) 배너
- 스코어보드, 기능 카드와 인접 배치
- 광고 클릭 유도 가짜 UI 요소
- 경기 카드 리스트 중간 삽입
- 한 viewport에 광고 2개 이상 노출
